Starlight Hangars website

## Updates

`updates.html` lists the updates. Each post is a static HTML page. Use `mike-goulian-aviation-pilot-installation.html` as the example; styling is shared in `assets/updates.css`.

1. **Create the article.** Copy the example to a descriptive filename such as `new-installation.html`. Keep `data-nav-section="updates"` on the body and the existing stylesheet/script references. Replace the headline, introduction, sections, and author. Add the confirmed publication date to the visible byline and `BlogPosting.datePublished` when publishing; use `dateModified` for later revisions.
2. **Add the evidence.** Explain what happened, what was tested, and what comes next. Identify software-validated layouts separately from results physically demonstrated in a hangar. Keep scenario assumptions alongside any capacity or performance claim.
3. **Add photos or recordings.** Store article media in `assets/updates/<article-name>/`. Use a small selection of compressed photos with meaningful alt text and captions. For a 3D example, start with a still and a short MP4 screen recording with playback controls, a poster image, and no autoplay. Preserve original logo proportions/colors. Describe what each layout or tow-path view demonstrates.
4. **Update the sharing information.** Change the page title, description, canonical URL, Open Graph fields, Twitter fields, and `BlogPosting` JSON-LD together. The canonical URL is `https://starlighthangars.com/<filename>`. Keep the headline, author, dates, and image consistent with the visible article. Add a 1200 × 630 share image in `assets/social/` and reference its public URL.
5. **List the article.** Add its title, image, link, short description, and publication date to `updates.html`, newest first. Put the date in a `<time class="updates-date" datetime="YYYY-MM-DD">` element at the top of the text side, followed by the title and description. Add the same URL/title to that page’s `ItemList` JSON-LD and keep list positions in order. A new post does not require changing the homepage.
6. **Refresh shared output.** Run `python scripts/sync_site.py --write`, then `python scripts/sync_site.py --check`. This updates the shared navigation/footer and sitemap, including the new article's canonical URL. The checked-in HTML is served directly; no build is needed to preview it. Edit shared navigation/footer in `scripts/partials/`, not inside generated comment blocks. Shared navigation, footer, and modal styles live in `assets/shared.css`.
7. **Review, then publish.** Check the article and listing on desktop and phone widths: navigation, images/video controls, captions, links, and demo button. Check that structured data parses and every media file exists. After publication, share the article’s public URL on LinkedIn; local URLs cannot produce a public preview. After a deployment, submit `https://starlighthangars.com/sitemap.xml` in Search Console/Bing Webmaster Tools and inspect the article URL there.

For local review, run `python -m http.server 55015 --bind 127.0.0.1` from the repository root and open `http://127.0.0.1:55015/`. If that server is already running, refresh the page.

SEO fields belong in each page's `<head>`: keep one canonical, a unique title/description, sharing metadata, and JSON-LD that matches the visible page. The homepage defines the company/site identities; About defines Samir's bio identity. Articles link their author to `about.html#samir-stevenson`, use an actual article photo in `BlogPosting.image`, and reference the company as publisher. Use factual content and internal links; no separate AI-only page is required.
